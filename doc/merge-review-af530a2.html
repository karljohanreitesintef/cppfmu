Commit 1 of 5 · 2026-09-18

Add combined FMI 2.0+3.0 build and port lifecycle state machine into FMI 3.0

Usage

  • The Conan option use_fmi_version gains the value "all" (previously 1 | 2 | 3). It requires both fmi2/2.0.4 and fmi3/3.0.2 and ships one static library plus both C API wrappers and both header sets.
  • The combined package deliberately sets no CPPFMU_USE_FMI_* define. A consumer of "all" must define CPPFMU_USE_FMI_3_0 per target when compiling the FMI 3.0 wrapper, and define nothing for the FMI 2.0 one. Single-version packages are unchanged and still carry the define on the target.
  • New CMake option CPPFMU_FMI_ALL, mutually exclusive with CPPFMU_FMI_1 and CPPFMU_FMI_3 (fatal error if combined).
  • FMI 3.0 hosts must now respect the state machine. A call made in a state the spec does not allow returns fmi3Error and never reaches the slave. The repo's own FMI 3.0 test had to be reordered because it called fmi3Reset before fmi3Terminate.

API

  • No change to cppfmu::SlaveInstance or cppfmu::SlaveInstance3 — the C++ author interface is untouched. All change is in the exported C ABI and in build configuration.
  • The FMI 3.0 module now exports the full fmi3Functions.h set. 13 entry points that did not exist before are added as refusing stubs: fmi3InstantiateModelExchange, fmi3InstantiateScheduledExecution, fmi3ActivateModelPartition, fmi3EnterContinuousTimeMode, fmi3CompletedIntegratorStep, fmi3SetTime, fmi3Set/GetContinuousStates, fmi3GetContinuousStateDerivatives, fmi3GetNominalsOfContinuousStates, fmi3GetEventIndicators.
  • The stubs log a refusal through the instance logger and return fmi3Error (the instantiation stubs return nullptr after logging), so an importer that dlsym's the whole table finds every symbol instead of failing to load.

Implementation

  • A per-instance state machine over Instantiated / Initialization / Step / Event / Terminated / Failed lives in fmi3_functions.cpp. Every uniform entry point routes through a RunLegalCall template that checks legality, calls the slave, applies the transition on success, and classifies throws.
  • Exception classification is now three-way: cppfmu::FatalError → fmi3Fatal + Failed latch; std::logic_error → fmi3Error with the instance left untouched (a violated precondition, not a failed simulation); any other std::exception or a non-exception throw → fmi3Error + Failed latch.
  • Failed is a latch: only freeing, resetting, or restoring a saved state escapes it.
  • CMake gains a combined branch that compiles cppfmu_cs.cpp as FMI 2.0 and cppfmu_cs_fmi3.cpp as FMI 3.0 via set_source_files_properties into one archive; the two produce disjoint symbols (SlaveInstance vs SlaveInstance3), and both test suites are built.
  • Net −265 lines in fmi3_functions.cpp despite adding 13 entry points, because the per-function try/catch scaffolding collapses into RunLegalCall.

Merge notes

two changes in one commit The "all" build and the strict lifecycle are independent and could be split if you want them landed separately.

The lifecycle is the part to scrutinise: any importer that was getting away with an out-of-order call sequence now gets fmi3Error. That is spec-correct, but it is a behaviour change for existing FMUs built on this branch, not a pure addition. The FMI 3.0 specification permits a Co-Simulation FMU to refuse such calls, so the strictness is defensible; the question is whether you want it on by default or behind a flag.

Commit 3 of 5 · 2026-09-19

03 32740cd 1 file · +477 / −978

Centralize FMI 1.0/2.0 dispatch behind a RunCall helper

Usage

  • Three behaviour changes reach FMI 1.0/2.0 consumers:
  • Null component handle now returns fmiError/fmi2Error instead of dereferencing a null pointer (previously undefined behaviour).
  • A throw that is not a std::exception is caught and translated to an error status instead of escaping across the extern "C" boundary.
  • Log messages change shape: category is now "cppfmu" instead of "", and the text is prefixed with the FMI function name. Anything downstream that parses log categories will see the difference.

API

None. Every exported FMI 1.0/2.0 symbol keeps its signature; only the body is rewritten.

Implementation

  • One file-local RunCall template replaces the cast, try/catch, status translation and logging repeated in 35 uniform delegators; each becomes a one-line lambda call.
  • Mirrors RunLegalCall in the FMI 3.0 layer, minus the lifecycle argument.
  • Instantiate, FreeInstance, DoStep, the status inquiries and the unsupported stubs stay bespoke — they do not fit the uniform shape.
  • Net −501 lines.

Merge notes

independent This commit touches only fmi_functions.cpp and has no dependency on the FMI 3.0 work, so it cherry-picks cleanly on its own.

Note it does not bring the std::logic_error distinction that the FMI 3.0 layer makes, so FMI 2.0 still treats every std::exception alike. The two layers are now structurally similar but not semantically identical — worth deciding whether you want them aligned.

Commit 4 of 5 · 2026-09-19

04 9754d1e 5 files · +580 / −213

Extract FMI 3.0 lifecycle into a testable Lifecycle module

Usage

  • No behaviour change intended — the same state graph, relocated. The "all" and FMI 3.0 builds now compile and install one more file pair.
  • CMAKE_EXPORT_COMPILE_COMMANDS is switched on repo-wide, so clangd and clang-tidy see each FMI 3.0 source with its CPPFMU_USE_FMI_3_0 macro instead of resolving the FMI 2.0 headers.

API

  • New installed public header cppfmu_lifecycle_fmi3.hpp (installed under both CPPFMU_FMI_3 and CPPFMU_FMI_ALL), exposing cppfmu::Lifecycle and cppfmu::LifecycleCall.
  • Lifecycle owns the state and is the only thing that can change it, through three named transitions: OnSuccess(call), Fail(), RestoreFromSnapshot(), plus the queries Allows(call) and CurrentState().
  • LifecycleCall is keyed by rule, not by entry point: every fmi3Get* is ReadVariable, every fmi3Set* is WriteVariable, and so on, with a distinct value only where the legal-state set or the transition differs.

Implementation

  • The whole state graph becomes one constexpr table of {call, legalStates bitmask, transition} rows in cppfmu_lifecycle_fmi3.cpp:
{LifecycleCall::EnterInitialization, kInstantiated, To(State::Initialization)},
{LifecycleCall::Terminate,           kRunning,       To(State::Terminated)},
{LifecycleCall::ReadVariable,        kReadable,      kNoTransition},
{LifecycleCall::DoStep,              kStep,          kNoTransition},
  • Removes MoveToStateOnSuccess, the ~10 scattered Is*/Allows* predicates and every inline InstanceState literal from fmi3_functions.cpp (net −57 lines there). Entry points now name only the call, never a target state.
  • fmi3DoStep and fmi3SetFMUState route their guard, Failed latch and conditional restore through the same module.
  • New tests/lifecycle_fmi3_test.cpp (208 lines) links only the Lifecycle module — no FMU, no slave, no C ABI — and walks every call's legal-state set, every transition, the Failed latch and the conditional restore. Registered as its own CTest target in the FMI 3.0 and combined builds.

Merge notes

the most reviewable piece If you take commit 1's lifecycle at all, this commit is what makes it auditable: the rules that were previously only reachable through the C entry points become a single table with a direct test.

Two things to weigh: it puts the header on the public installed surface (you may prefer it internal), and turning on CMAKE_EXPORT_COMPILE_COMMANDS globally is an unrelated tooling change riding along in the same commit.

Both are improvements, both are observable from outside — worth a release-note line each, and worth confirming no downstream tooling keys off the old log category.
